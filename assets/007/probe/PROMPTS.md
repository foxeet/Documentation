# 两条小样的 prompt

说明:

- 这两条小样当时没有单独的 prompt, 是对照参考截图和案例视频直接写的代码. 下面两段是按实际做出来的内容整理的, 可以交给能执行命令的编程 Agent (例如 Claude Code) 复现.
- 这两段 prompt 没有单独完整跑过, 出来的画面会和 `engine.html` 里的版本有差异.
- 环境: Node 22, ffmpeg, Playwright (自带 Chromium).
- 使用时把参考截图一起发给模型, 效果更接近.
- 更省事的做法: 直接把本目录的 `engine.html` 交给模型当起点, 让它在此基础上改.

## 1. 仿小Lin说的数据对比素材 (透明背景)

```text
任务: 做一个带透明背景的动态数据图形素材, 用来叠加在口播视频上. 风格参考我附的截图 (财经科普视频里的 "收购金额对比" 嵌套圆图).

内容 (全部来自下面这份数据, 不要写死在代码里):
[
  {"outer": "微软", "outerEn": "Microsoft", "inner": "动视暴雪", "innerEn": "Activision Blizzard", "value": 687, "at": 0.2},
  {"outer": "马斯克", "outerEn": "Elon Musk", "inner": "推特", "innerEn": "Twitter", "value": 440, "at": 2.6}
]
金额前缀 "$", 单位 "亿". "at" 是这一组出现的时间 (秒).

画面:
- 画布 1920x1080, 30fps, 总长 6 秒, 背景完全透明.
- 每组数据是一个大圆 (收购方) 套一个小圆 (被收购方):
  - 大圆上部: 收购方中文名, 特粗字体, 两侧各有一条点状细线; 下面一行小号英文名.
  - 大圆下部: 一个小圆, 里面是被收购方中文名和小号英文名.
  - 大圆底边上压着一个深色的金额标签, 带同色描边, 内容形如 "$ 687 亿".
- 大圆的面积和金额成正比 (半径按金额的平方根缩放).
- 第一组用绿色, 第二组用蓝色, 第三组以后依次用紫色, 橙色. 圆是半透明玻璃质感: 径向渐变, 一圈细亮边, 外发光.
- 不要使用任何公司的 logo, 只用文字.

动画:
- 每组出现时: 大圆弹出 (0.6 秒, 带一点回弹) -> 名称淡入上移 -> 小圆弹出 (晚 0.6 秒) -> 金额标签落下 (晚 1.0 秒), 数字用 1 秒从 0 滚动到目标值.
- 新的一组出现时, 已有的组平滑移动让出位置 (0.75 秒, 缓入缓出), 所有组始终整体居中.
- 全部出现后保持轻微的呼吸感缩放, 不要静止.

版式要自动适应:
- 往数据里加第三组, 第四组时自动重排, 超出画面宽度就整体缩小.
- 画布改成 1080x1920 时自动改为纵向排列.

技术要求:
- 一个 HTML 文件, 不依赖外部网络. 中文字体用 Noto Sans SC (400, 700, 900), 从 npm 包 @fontsource/noto-sans-sc 本地加载.
- 所有动画由一个纯函数 render(t) 驱动: 给定时间 t (秒), 直接算出每个元素的样式. 不用 CSS animation 或 transition, 不用 Date.now 和 Math.random. 同一个 t 必须得到完全相同的画面.
- 写一个 Node 渲染脚本: 用 Playwright 的无头 Chromium 逐帧调用 render(t) 并截图 (PNG, omitBackground: true), 通过管道交给 ffmpeg. 截图前先等字体加载完成.
- 输出三个文件: 带透明通道的 MOV (ProRes 4444), 带透明通道的 WebM (VP9, yuva420p), 以及一个叠在深灰底色上的预览 MP4.

自检 (渲染全片之前先做):
- 截取 1.5, 2.4, 3.4, 5.5 秒四帧, 拼成一张图自己看一遍.
- 检查: 文字有没有溢出圆或互相遮挡; 金额标签有没有盖住名称; 所有元素是否都在画面内; 两组的大小比例是否和金额相符.
- 有问题先修, 修完再渲染全片. 最后告诉我输出文件的路径, 以及你检查时发现并修掉了什么.
```

## 2. 带等距方块的科技宣传片 (26 秒)

如果只要方块那一个镜头, 保留 "整体风格", "场景 5", "等距方块的做法", "渲染" 和 "自检" 几部分即可.

```text
任务: 做一条 26 秒的科技公司宣传动画 (MG 动画), 1920x1080, 30fps. 品牌是虚构的: 中文名 "星图数据", 英文名 "StarBrain", 域名 "xingtu.example". 风格参考我附的截图: 深蓝紫色科技风, 等距方块, 发光线条.

整体风格:
- 背景: 蓝紫色斜向渐变, 上面有很淡的网格, 缓慢上升的发光小点, 几条竖直的光带. 背景贯穿全片, 不随场景切换而中断.
- 配色: 强调色青绿 (#22d9c9 到 #1fdc9a), 暖色橙黄 (#ffb020), 卡片底色深蓝 (#1a2a6c). 文字白色, 中文用 Noto Sans SC 特粗.
- 每个场景底部居中有一行字幕 (44px, 白字, 深蓝色阴影).
- 场景之间: 进场 0.35 秒淡入并从 1.07 倍缩到 1 倍, 出场 0.3 秒淡出.

六个场景:
1. 数据亮点 (4.5 秒). 画面中央一个青绿渐变的发光圆, 里面的数字从 38% 滚动到 90%. 周围有 7 张小的仪表盘卡片 (折线图, 柱状图, 列表, 饼图, 表格) 从外向内飞入并缓慢漂浮. 圆的外面有两圈旋转的虚线环. 数字滚动结束时向外扩散一圈光环. 字幕: "占据 90% 的出海游戏投放市场份额".
2. 三大优势 (4.5 秒). 上方横排三个圆环图标 (外圈青色发光, 内圈橙色并持续旋转, 中间是简单的图形符号), 下面是标签: "有效策略", "海量数据", "先进的工具支持". 画面下方是一个椭圆形的全息平台 (几圈同心椭圆, 其中两圈的虚线在流动), 平台上站着十来个小人图标. 平台向上打出一束梯形的光, 光里有白色的小光柱不断上升. 字幕: "有效策略, 海量数据和先进的工具支持".
3. 品牌亮相 (4.5 秒). 中央一个紫蓝渐变的大圆, 里面是一个简单的三角形几何标志, 品牌名和域名. 圆的外面有三圈转速不同的刻度环. 左右各飞入一张标签卡片 ("应用商店数据库", "独创的工具"), 各有一条连线画向中心圆. 两个小光球沿椭圆轨道环绕. 字幕: "庞大的应用数据库和独创的工具".
4. 大数字 (4 秒). 画面中央一个巨大的 "1000+" (约 350px, 白色, 带青色的错位阴影), 数字从 0 快速滚动到 1000, 结束后 "+" 弹出. 数字后面漂浮着 7 张仪表盘卡片. 字幕: "结合超 1000+ 案例的投放经验".
5. 等距方块 (4.5 秒). 等距视角的场景: 地面是一块发光的网格; 中央一个扁平的平台, 上面叠一块带芯片纹理的小平台; 四个角上各有一摞两层的蓝色方块, 上层方块悬浮并轻微上下浮动. 远处两摞方块的上方各有一道向上的光束和一个标签 ("ASO", "Search Ads"). 中央平台上方悬浮着品牌标志的圆形徽章. 所有方块从高处依次落下就位. 字幕: "打通 ASO 和搜索广告数据".
6. 收尾 (4 秒). 中央一朵蓝紫渐变的云, 云里有电路板样式的线条依次画出, 线的末端有小圆点. 云的中部是一个白色的胶囊形进度条, 左边写着 "StarBrain", 右边的青绿色进度不断增长. 云的下方有三道向下的光柱在闪动. 云整体轻微上下浮动. 字幕: "现在就搭上星图 StarBrain 的快车".

结构要求 (这部分很重要, 关系到以后能不能改):
- 视频内容用一份 JSON 文档描述: 画布, 主题色, 场景列表. 每个场景有 id, 类型, 时长, 字幕和参数 (数字, 文字, 标签等). 所有文字和数字都从这份文档读取.
- 每种场景写成一个组件, 提供 build(root, props) 和 update(state, 场景内时间) 两个函数. 运行时按顺序挂载场景, 并提供 render(t).
- 所有颜色都通过主题变量 (CSS 变量) 引用, 组件里不要出现写死的品牌色. 验收标准: 只改 JSON 里的主题色和品牌名, 整条片子就能换成另一个品牌, 不留原来的颜色.
- 动画全部由 render(t) 这个纯函数驱动: 不用 CSS animation 或 transition, 不用 Date.now; 随机数用固定种子. 同一个 t 必须得到完全相同的画面.

等距方块的做法 (场景 5):
- 用 CSS 3D, 不要用图片. 外层容器: transform-style: preserve-3d; transform: rotateX(60deg) rotateZ(45deg).
- 每个方块三个面: 顶面 translateZ(高度); 正面放在 top:100%, transform-origin: top, rotateX(90deg); 侧面放在 left:100%, transform-origin: left, rotateY(-90deg). 三个面用深浅不同的蓝色.
- 标签, 光束和徽章要始终正对镜头: translate3d(x, y, z) rotateZ(-45deg) rotateX(-60deg).
- 只给远处的两摞方块加标签. 近处的方块如果也加, 标签会和远处的方块重叠.

渲染:
- 一个 HTML 文件, 不依赖外部网络. 字体用 npm 包 @fontsource/noto-sans-sc, 截图前等字体加载完成.
- 写一个 Node 渲染脚本: Playwright 无头 Chromium 逐帧调用 render(t) 并截图, 通过管道交给 ffmpeg, 输出 H.264 MP4.
- 按场景分段渲染并缓存: 每个场景的缓存键由该场景的内容, 开始时间和主题算出. 内容没变的场景直接复用, 最后把各段拼接起来. 同时开 3 个进程并行渲染.

自检 (渲染全片之前先做):
- 每个场景截两帧 (中段和结尾前), 拼成一张图自己看一遍.
- 检查: 文字溢出或互相遮挡; 元素越出画面或压住字幕; 等距场景里方块的前后遮挡关系是否正确; 每个场景的主体是否够大 (不要缩在画面中间一小块).
- 有问题先修, 修完再渲染全片. 最后告诉我输出文件的路径, 以及检查时发现并修掉了什么.
```

## 3. 后续修改的说法

第一版出来之后, 修改不需要重写, 直接说要改什么:

```text
把场景 1 的 90% 改成 95%, 场景 4 改成 1200+, 字幕同步修改. 只改 JSON 文档, 然后重新渲染, 告诉我重新渲染了几个场景.
```

```text
换一个品牌: 主色改为橙色 (#fb923c), 背景改为深棕色, 品牌名改为 "橙象科技" 和 "OrangeBrain". 只改 JSON 里的主题和文字. 渲染后截图检查有没有残留的旧颜色, 有的话把对应组件改成引用主题变量.
```

```text
在数据里加一组: 博通 收购 VMware, 610 亿美元, 在 4.8 秒出现, 总长延到 8.5 秒. 再输出一个 1080x1920 的竖屏版本.
```
